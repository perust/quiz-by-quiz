매일 퀴즈 문제를 자동으로 분석·생성·검증·백업하는 7단계 파이프라인을 실행합니다.
카테고리당 1개씩 총 4개(한국사, 과학, 지리, 예술과문화)를 추가합니다.
매개변수 없이 분석 결과에 따라 난이도와 정답 번호를 자동 결정합니다.

- 각 단계 끝에서 오류가 발생하면 **이후 단계를 실행하지 않고 즉시 중단**하며, 어떤 단계에서 어떤 오류가 발생했는지 보고합니다.
- 모든 출력은 `## Step N: 제목` 헤더로 구분합니다.
- 상태 표시: ✅ 성공 / ⚠️ 주의 / ❌ 실패

1. `quiz-challenge/src/data/questions.ts` 파일을 읽습니다.
2. Question 타입 구조를 확인합니다 (id, category, difficulty, question, options, answer, explanation).
3. 파일이 존재하지 않거나 파싱에 실패하면 → **중단** + 오류 보고.

quiz-stats 형식으로 현재 상태를 분석합니다.

| 항목 | 값 |

### 2-2. 카테고리별 난이도 분포

## Step 3: 카테고리별 부족한 부분 파악 및 자동 결정

### 3-1. 난이도 자동 결정

각 카테고리(한국사, 과학, 지리, 예술과문화)에 대해:

1. 현재 난이도 분포와 권장 비율(3:4:3)의 편차를 계산합니다.
2. 편차가 가장 큰(부족한) 난이도를 해당 카테고리의 새 문제 난이도로 결정합니다.
3. 편차가 동일하면 `보통` > `쉬움` > `어려움` 순으로 우선합니다.

### 3-2. 정답 번호 자동 배정

1. 전체 정답 분포에서 가장 부족한 번호 4개를 정렬합니다.
2. 4개 카테고리에 각각 배정합니다 (가장 부족한 번호부터 순서대로).
3. 동일 비율이면 0 > 1 > 2 > 3 순으로 우선합니다.

### 3-3. 결정 결과 출력

| 카테고리 | 결정된 난이도 | 결정 사유 | 배정된 정답 번호 | 배정 사유 |
|----------|---------------|-----------|------------------|-----------|

**이 단계에서 오류가 발생하면 이후 단계를 실행하지 않고 즉시 오류를 보고합니다.**

## Step 4: 새 문제 생성 및 중복 체크

### 4-1. 문제 생성

4개 카테고리 각각에 대해 Step 3에서 결정된 난이도·정답 번호로 문제 1개씩 생성합니다.

```typescript
{
  id: <마지막 ID + 순번>,
  category: "<카테고리>",
  difficulty: "<난이도>",
  question: "<문제>",
  options: ["<보기1>", "<보기2>", "<보기3>", "<보기4>"],
  answer: <0~3>,
  explanation: "<해설>"
}
```

### 4-2. 중복 검사 (quiz-check 기준)

각 생성된 문제에 대해:

1. 기존 문제와 **주제(question)**가 동일하거나 매우 유사한지 확인합니다.
2. 같은 정답을 묻는 다른 형태의 문제가 있는지 확인합니다.
3. 중복이 발견되면 → **해당 문제만 재생성**합니다 (최대 3회 시도).
4. 3회 재생성 후에도 중복이면 → **중단** + 오류 보고.

### 4-3. 중복 검사 결과

| 카테고리 | 문제 요약 | 중복 여부 | 유사 문제 ID | 재생성 횟수 |
|----------|-----------|-----------|-------------|-------------|

**이 단계에서 오류가 발생하면 이후 단계를 실행하지 않고 즉시 오류를 보고합니다.**

## Step 5: 문제 검증 및 파일 삽입

### 5-1. 검증 가이드라인 (quiz-add + quiz-validate 기준, 필수 준수)

생성한 4개 문제 각각이 아래 기준을 **모두** 충족하는지 확인합니다.

#### 정답 유일성
- 정답이 하나뿐인지 확인합니다.
- 다른 해석이 가능하면 조건을 명시합니다 (예: "면적 기준", "2024년 기준").

#### 최상급·단정 표현 검증
- 아래 표현이 포함된 경우 **측정 기준**을 반드시 명시합니다:
  - 가장, 최초, 최대, 최소, 최고, 최저, 최선, 최악
- 아래 단정 표현이 포함된 경우 **범위를 한정**합니다:
  - 유일한, 반드시, 절대, 항상, 모든
- 논란 가능한 내용은 "전통적으로", "중 하나" 등으로 완화합니다.

#### 시간·범위 명확성
- 변할 수 있는 정보에는 시점을 명시합니다.
- 지리적·분류적 범위를 한정합니다.

#### 사실 정확성
- 의심스러운 정보는 **웹 검색으로 교차 검증**합니다.
- 수치 데이터는 최신 공인 데이터를 사용합니다.

#### 오답 보기 품질
- 오답 보기가 그럴듯하되, 명확히 틀린 것이어야 합니다.
- 정답과 혼동될 수 있는 함정 보기를 포함합니다.

### 5-2. 검증 결과

각 문제에 대해:

| 카테고리 | 정답 유일성 | 최상급·단정 | 시간·범위 | 사실 정확성 | 오답 품질 | 종합 |
|----------|-------------|-------------|-----------|-------------|-----------|------|

- **종합**: ✅ 전체 통과 / ⚠️ 수정 후 통과 / ❌ 실패
- 검증 실패 항목이 있으면 → **해당 문제를 수정하거나 재생성**합니다.
- 수정 후에도 검증을 통과하지 못하면 → **중단** + 오류 보고.

### 5-3. 파일 삽입

- questions 배열의 **마지막 요소 뒤**에 4개 문제를 삽입합니다.
- 기존 코드 스타일(들여쓰기, 쉼표, 주석)을 정확히 따릅니다.
- 삽입 후 TypeScript 문법 오류가 없는지 확인합니다.

**이 단계에서 오류가 발생하면 이후 단계를 실행하지 않고 즉시 오류를 보고합니다.**

   ```
   - 총 문제 수: <이전> → <이후>

   Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>
   ```
3. `git commit` 실행
4. 커밋 실패 시 → **중단** + 오류 보고.
