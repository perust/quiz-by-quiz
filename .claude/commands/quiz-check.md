`quiz-challenge/src/data/questions.ts`의 모든 문제에 대해 정답의 정확성을 검증합니다.

## 카테고리 필터

- `$ARGUMENTS` 값이 있으면 해당 카테고리(한국사, 과학, 지리, 예술과문화)의 문제만 검증합니다.
- `$ARGUMENTS` 값이 비어 있으면 전체 문제를 검증합니다.

## 작업 순서

### 1. 파일 읽기

1. `quiz-challenge/src/data/questions.ts` 파일을 읽습니다.
2. `$ARGUMENTS`가 지정된 경우 해당 카테고리의 문제만 필터링합니다.

### 2. 각 문제에 대해 아래 항목을 검증합니다

#### 2-1. 정답 인덱스 유효성
- `answer` 값이 0~3 범위 내인지 확인합니다.
- `options` 배열의 길이가 정확히 4인지 확인합니다.

#### 2-2. 정답 내용 정확성
- `question`과 `options[answer]`의 조합이 사실에 부합하는지 확인합니다.
- 의심스러운 문제는 **웹 검색으로 교차 검증**합니다.
- 검증 시 아래 항목을 중점 확인합니다:
  - 연도, 인물, 장소 등 고유명사의 정확성
  - 수치 데이터의 최신성 (공인 기관 기준)
  - 과학적 사실의 학술적 합의 여부

#### 2-3. 오답 보기 검증
- 오답 보기 중 정답으로 해석될 수 있는 것이 없는지 확인합니다.
- 모든 보기가 문제 맥락에 적합한지 확인합니다.
- 명백히 틀린 보기만 있어 소거법으로 쉽게 풀리지 않는지 확인합니다.

#### 2-4. 해설 정확성
- `explanation`이 정답을 올바르게 설명하는지 확인합니다.
- 해설 내 수치, 연도, 고유명사가 정확한지 확인합니다.
- 해설이 오답인 이유까지 설명하면 더 좋지만, 최소한 정답 근거는 포함해야 합니다.

#### 2-5. 중복 검사
- 동일하거나 매우 유사한 문제가 있는지 확인합니다.
- 같은 정답을 묻는 다른 형태의 문제가 있으면 표시합니다.

### 3. 결과 출력

#### 3-1. 문제별 검증 결과

| # | ID | 카테고리 | 문제 (요약) | 정답 | 인덱스 | 정확성 | 해설 | 비고 |
|---|----|----------|-------------|------|--------|--------|------|------|

- **정확성** 열: ✅ 정확 / ⚠️ 확인필요 / ❌ 오류
- **비고** 열: 문제가 있는 경우 구체적 설명

#### 3-2. 오류/주의 사항 상세

문제가 발견된 항목만 별도로 상세 설명합니다:

```
🔴 [ID: ?] 오류 — 설명
🟡 [ID: ?] 주의 — 설명
```

#### 3-3. 중복 문제 목록

유사하거나 중복된 문제 쌍이 있으면 나열합니다:

| 문제 A (ID) | 문제 B (ID) | 유사도 | 설명 |
|-------------|-------------|--------|------|

#### 3-4. 종합 요약

| 항목 | 결과 |
|------|------|
| 총 검증 문제 수 | |
| ✅ 정확 | |
| ⚠️ 확인필요 | |
| ❌ 오류 | |
| 중복 의심 | |

### 4. 수정 제안

오류 또는 확인필요 항목에 대해 구체적인 수정안을 제시합니다.
수정안은 기존 코드 형식을 그대로 따르되, 사용자 승인 없이 파일을 수정하지 않습니다.
