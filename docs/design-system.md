# quiz by quiz 디자인 시스템

> 기준: `css/voxel-theme.css`(토큰·시각 언어)와 `css/style.css`(구조·동작 계약).
> 잠금: `tests/design-system.test.mjs`. 화면 흐름 점검: `tools/check-screens.js`.

## 1. 방향

**world-first cozy pixel game.** 월드는 별도 카드 안의 장식이 아니라 모든 화면을 잇는 주 표면이다.
게임 월드가 화면의 70–80%를 차지하고, 크롬(버튼·카드·HUD·폼)은 가장자리의 작은 슬롯과 필요한 순간의
상황별 overlay로만 올라온다. 한 픽셀 언어는 **캐릭터 · 아이콘 · 배경 월드 · arena**가 함께 맡는다.

예전 화면은 모든 요소가 서로 다른 파스텔 카드·굵은 테두리·하단 그림자·창 장식을 가져 시선이
흩어졌고, 픽셀 글꼴이 본문까지 덮어 장난감처럼 보였다. 그래서 다음을 원칙으로 삼는다.

1. 한 화면의 주 행동 수를 최소화한다. 홈은 게임 진입점인 **온라인·전체 도전 둘**, 결과는 다시 하기, 시트는 다음 문제만 채운다.
2. 홈에서는 월드 자체가 메뉴다. 닉네임·설정·캐릭터·랭킹은 edge HUD, 분야와 온라인·전체 도전은 하단 game dock이다.
3. 큰 패널은 질문·피드백·결과·설정·방 만들기처럼 읽거나 결정해야 할 때만 쓴다.
4. 같은 무게의 카드를 늘어놓지 않는다. 목록은 **overlay 하나 안의 줄**로, 줄 사이는 1px 선으로만 나눈다.
5. 색은 **깊은 보라 HUD + 반투명 중립 overlay + 민트·코랄·골드 의미색**뿐이다. 분야 색은 아이콘 칸에만 쓴다.
6. 상태는 **색만이 아니라 모양·표식·테두리·높이**로도 구분한다 (FR-4.1, FR-4.2, FR-3.9).
7. 제품에 없는 데이터(레벨·재화·업적·힌트 수)를 그려 넣지 않는다.
8. 월드는 캐릭터가 쓰는 **큰 정사각 픽셀·단단한 외곽선·단계형 명암**을 쓴다. 매끈한 3D
   복셀 렌더·회화식 질감·피사계 심도는 섞지 않고, 캐릭터가 걷는 중앙은 낮은 디테일로 비워 둔다.

## 2. 두 파일의 역할

| 파일 | 갖는 것 | 갖지 않는 것 |
| --- | --- | --- |
| `css/style.css` | 배치(grid·flex), 크기·손가락 목표(44px), 위치(흐름형 피드백·fixed 스틱·워커), 간격 토큰 사용, 사용자 선택·터치 동작, 워커 몸짓, 대기실 방 그림과 구조에 묶인 토큰 상태 | 일반 UI 컴포넌트의 시각 문법, 장식 밖 raw 색·글꼴·그림자·모서리 |
| `css/voxel-theme.css` | `@font-face`, 모든 토큰, 아이콘 묶음, 글자, 표면, 컴포넌트의 모양과 상태, 월드 배경, 반응형 모양, 움직임 | 배치 계약을 새로 정의하는 규칙 |

- 파일 이름 `voxel-theme.css` 는 로딩·테스트 계약 때문에 그대로 두었다. 안은 이 문서의 디자인 층이다.
- 두 파일은 언제나 함께 로드된다 (`index.html`, 기본 → 디자인 층 순). 디자인 토큰은 쓰는 자리에서
  fallback 값을 적지 않는다. 런타임 측정값인 `--home-dock-h`만 초기 fallback을 갖는다.
- `css/assets/world-academy-pixel-mobile.webp`와 `world-academy-pixel-desktop.webp`는 캐릭터와 같은
  큰 픽셀·단단한 외곽선·단계형 명암의 원본 배경이다. 글자·로고·UI를 포함하지 않으며 좁은 세로 화면은
  세로 art를, 너비 600px 이상 또는 가로 화면은 가로 art를 써서 과도한 중앙 crop을 피한다.
- 한 컴포넌트를 고칠 때는 두 파일의 **같은 이름 섹션**을 함께 본다.
- **세계 장식**만 날 색·자유 치수를 쓴다: 복셀 마을(`.voxel-*`, `.iso-cube*`), 대기실 가구·액자
  (`.lounge__chair|sofa|table|seat|portrait*`), 캐릭터 몸통과 몸짓(`.walker__body|face|dot|shadow`,
  `.walker--sad|seated|walking|idle|hop`). 이 목록은 `tests/design-system.test.mjs` 의 `DECOR` 하나뿐이다.

대비 (`tests/voxel-theme.test.mjs` 가 계산해 잠근다):
작은 글자는 제 바탕에서 4.5:1 이상 — 흰 글자/보라·민트·코랄, 보라 글자/옅은 보라, 민트·코랄·골드 글자/
제 옅은 바탕과 흰 바탕, 보조 글자/흰·페이지·칸·트랙 바탕, 분야 색/분야 옅은 색, 브랜드/하늘 패널.
입력칸 선·초점 고리·주 행동 채움은 흰 바탕에서 3:1 이상 (WCAG 1.4.11).
반투명 표면은 글자에 가장 불리한 그림 위에 얹은 색으로 잰다 — HUD(`--hud-bg`·`--hud-bg-soft`)는 흰 구름 위,
유리(`--world-glass`)는 검은 그림자 위. HUD 위 흰·옅은 글자와 `--hud-warning` 은 4.5:1, `--focus-on-hud` 고리는 3:1,
유리 위 본문·보조·경고·보라 글자는 4.5:1 이상이다.

### 간격 — 4px 미세 / 8px 기본

| 토큰 | 값 | 토큰 | 값 |
| --- | --- | --- | --- |
| `--space-1` | 4px | `--space-6` | 24px |
| `--space-2` | 8px | `--space-8` | 32px |
| `--space-3` | 12px | `--space-10` | 40px |
| `--space-4` | 16px | `--space-12` | 48px |
| `--space-5` | 20px | `--space-16` | 64px |

- margin·padding·gap 은 이 토큰(또는 0·auto·`env(safe-area-inset-*)`)만 쓴다. 계산이 필요하면
  `calc(var(--icon-tile) + var(--space-3))`처럼 공간을 차지하는 크기 토큰과 간격 토큰을 더한다.
- 바깥 여백 `--page-pad` 는 16px, 420px 이하에서 12px 이다 (`:root` 하나만 바뀐다).
- 테스트가 막는 예외 숫자는 4의 배수뿐이다. 이동 UI 여백은 literal 합계가 아니라 공용 크기 토큰에서 계산한다.

### 크기·모서리·테두리·높이

| 무리 | 토큰 |
| --- | --- |
| 크기 | `--tap` 44px(손가락 목표) · `--tap-lg` 52px(시트 버튼) · `--icon-sm/md/lg` 16/20/24px · `--icon-tile` 40px · `--content-max` 680px · 이동 UI `--walk-stick/knob/confirm-size` 96/48/72px(짧은 화면 80/40/64px) · `--walker-width/height` 34/42px · `--screen-walker-width/height` 40/48px · `--lounge-floor` 176px |
| 모서리 | `--radius-xs` 4 · `-sm` 8 · `-md` 12 · `-lg` 16 · `-xl` 24 · `-full` 999 (원은 `50%`) |
| 테두리 | `--border-1` 1px(기본 담기) · `--border-2` 2px(상태가 바뀌는 게임 조각) — 두 종류뿐 |
| 높이 | `--elevation-1` 쉬는 패널·버튼 · `--elevation-2` 떠 있는 조각(hover 보기, 손가락 조작부, 말풍선) · `--elevation-3` 덮는 것(대화상자, 피드백 시트) — 세 단계뿐 |
| 표식 | `--press-edge` 채운 버튼의 두께(누르면 사라짐) · `--marker-mine` 목록 줄의 «내 것» 왼쪽 4px 띠 |

`box-shadow` 에는 이 다섯 토큰과 `none` 만 쓴다. 카드마다 굵은 하단 그림자·이중 테두리·창 점을 두지 않는다.

### 글자

| 토큰 | 값 |
| --- | --- |
| `--font-text` | `-apple-system, BlinkMacSystemFont, 'Apple SD Gothic Neo', 'Pretendard', 'Noto Sans KR', 'Malgun Gothic', system-ui, sans-serif` |
| `--font-display` | `'NeoDunggeunmo'` + 같은 시스템 글꼴 |
| 크기 | `--text-xs` 12 · `-sm` 14 · `-md` 16 · `-lg` 18 · `-xl` 20 · `-2xl` 24 · `-3xl` 32 · `-4xl` 48 |
| 줄 높이 | `--leading-tight` 1.25 · `-snug` 1.4 · `-normal` 1.6 |
| 굵기 | `--weight-bold` 700 · `--weight-heavy` 800 (픽셀 글꼴은 400) |

- **본문은 시스템 글꼴이다.** 질문(18–20px)·보기(16px)·해설(16px)·설명·버튼·폼은 모두 `--font-text`.
- **픽셀 글꼴은 짧은 표식에만 쓴다**: 브랜드 `quiz by quiz`, 문항 위치 `3 / 10`, 보기 번호, 무대 칸 번호,
  결과 점수와 등급, 랭킹·최종 순위 숫자. 이 목록 밖에 쓰면 테스트가 실패한다. 일반 UI에서는
  `--text-*` 단계만 쓰며, 홈 마을 안의 작은 시계처럼 실제 픽셀 그림을 이루는 글자는 장식 예외다.
- 일반 UI 글자는 12px 아래로 내리지 않는다. 입력칸은 16px 이다 — 아래로 내리면 iOS 가 입력할 때 화면을 확대한다.

### 움직임

`--duration-fast` 120ms(hover·누름) · `--duration-base` 160ms(상태 전환·정답 pop·오답 shake) ·
`--duration-slow` 180ms(시트 올라오기). `--ease-out`, `--ease-in-out`.

- 화면 피드백은 100–180ms 안에 끝난다. **끝없이 깜빡이는 경고를 두지 않는다** — 남은 5초는 아이콘
  (시계 → 경고)·글(«5초 남았어요»)·색이 함께 바뀌어 알린다. 글은 재촉하지 않고 남은 양만 말한다 (PRD 2.1).
- 캐릭터의 걷기·제자리 뛰기·한 번 뛰기는 화면 피드백이 아니라 몸짓이라 `style.css` 에 있다
  (`walker-land` 이름은 `walker.ts` 가 기다리므로 바꾸지 않는다). 제자리 뛰기도 끝없이 돌지 않는다 —
  멈춰 선 뒤 **세 번**(약 3.3초, WCAG 2.2.2의 5초 안)만 뛰고, 다시 멈추거나 고를 때 처음부터 센다.
- `prefers-reduced-motion: reduce` 에서는 모든 animation·transition 을 끄고 반복을 한 번으로 줄인다.
  설정의 **움직임 줄이기**(`html[data-motion='reduce']`, U55)도 **같은 선언**이다 — 기기 설정을 모르는 사람도
  앱 안에서 캐릭터의 제자리 뛰기·걷기 튐과 화면 효과를 멈춘다. 두 블록은 함께 고친다(`tests/settings-dialog.test.mjs`).
  스크립트가 움직이는 스크롤도 같은 두 신호를 본다 — `scrollIntoView` 의 `behavior` 는 `ui/motion.ts` 의
  `scrollBehavior()` 로만 고르고(줄이면 `auto`), `'smooth'` 를 직접 쓰지 않는다. 직접 넘긴 `smooth` 는 CSS 의
  `scroll-behavior: auto` 를 건너뛴다.

## 4. 아이콘

- **24×24 격자 위의 12×12 픽셀**(한 점 = 2 단위)로 직접 그린 묶음이다. 외부 에셋을 복사하지 않았다
  (Pixelarticons 의 «한 격자로 통일» 원칙만 참고).
- 토큰 `--i-<이름>` 은 SVG data URI 이고, 화면에는 `mask` 로 그려 **색은 언제나 `currentColor`** 다.
- 쓰는 법은 두 가지다.
  - 요소 자체: `<span class="icon" data-icon="refresh" aria-hidden="true"></span>`
  - 칸 안의 아이콘: 칸 요소에 `data-icon` 을 달면 `::before` 가 그린다
    (`.menu-card__figure`, `.category-card__icon`, `.challenge-card__icon`, `.room-item__icon`,
    `.online-action-card__icon`, `.online-panel-heading__icon`, `.room-empty__icon`, `.result-stats__item`)
- 상태 표식은 상태 클래스가 고른다 (보기 알약 ✓ ✗ ⧗, 무대 칸 ✓ ✗, 타이머 시계·경고, 대기실 왕관·준비 ✓·연결 끊김 경고).
  그래서 TS 는 글리프를 쓰지 않고 뜻 글자(«정답», «오답», «제출됨»)만 남긴다.
- 채운 배지 위의 흰 아이콘은 `--i-check-inverse`·`--i-cross-inverse` 를 배경으로 얹는다(mask 를 쓰면 배지 바탕까지 깎인다).
  `select` 화살표는 의사 요소가 없어 `--select-chevron`(색이 든 그림)을 쓴다.
- 아이콘은 모두 `aria-hidden` 이다. 뜻은 버튼 이름·글자·`aria-pressed` 가 말한다.
- 강제 색상(고대비) 모드는 mask 아래의 배경색을 지운다. `currentColor` 로 칠하는 mask 아이콘을 더하면
  `voxel-theme.css` 28절 목록(또는 그 곁의 `forced-colors` 블록)에 함께 넣어 `CanvasText` 로 다시 칠한다 —
  `tests/forced-colors-icons.test.mjs` 가 mask 아이콘을 모두 찾아 빠진 것을 잡는다.
- 번들 픽셀 글꼴에 없는 글리프(✓ ✗ ⏱ ⚠ ♛ ← ↻ ⚙ ★ 등)를 아이콘으로 쓰지 않는다. 화살표는 조작법의
  `<kbd>` 키 이름으로만 남는다.

| 이름 | 뜻 | 이름 | 뜻 |
| --- | --- | --- | --- |
| `check` / `cross` | 정답·준비·선택됨 / 오답 | `book` `flask` `globe` `bulb` `music` | 한국사·과학·지리·일반상식·예술과문화 |
| `clock` / `alert` | 남은 시간 / 경고·오류 | `grid` | 전체 도전 방 |
| `hourglass` | 서버 채점 기다림 · 게임 중인 방 | `palette` `trophy` `users` | 캐릭터 · 랭킹 · 온라인 |
| `question` | 조작법 | `user` `pencil` | 내 닉네임 · 바꾸기 |
| `play` | 전체 도전 시작 | `search` `key` `plus` | 방 찾기 · 코드 참가 · 방 만들기 |
| `sound-on` / `sound-off` | 설정의 소리 토글 | `lock` `crown` | 비밀번호 잠금 · 방장 |
| `gear` | 설정 (앱 바) | | |
| `arrow-left` `refresh` `filter` | 돌아가기 · 새로고침 · 필터 | `star` `target` `info` | 기록 · 정답률 · 안내 |

**아이콘을 더하는 법**: 12×12 점 그림을 SVG path(2 단위 사각형들)로 만들어 `:root` 에 `--i-<이름>` 으로
넣고 `[data-icon='<이름>'] { --icon: var(--i-<이름>); }` 한 줄을 더한다. 테스트가 경로의 숫자가 2의
배수인지까지 본다. 카테고리를 더할 때는 `src/constants.ts` 의 `icon` 에 이 목록의 이름을 쓰면 CSS 를
고치지 않아도 된다 (분야 색이 없으면 브랜드 보라로 그린다).

## 6. 컴포넌트와 상태

### 버튼

| 종류 | 쉬는 | hover (마우스) | 눌림 | 꺼짐 |
| --- | --- | --- | --- | --- |
| 주 행동 `.button--primary` | 보라 채움 + 두께 + 높이 1 | 진한 보라 | 두께·그림자 사라지고 2px 내려앉음 | 옅은 회색 바탕, 흐린 글자, 그림자 없음 |
| 보조 `.button--ghost` | 흰 바탕 1px 선 | 옅은 보라 바탕·선·글자 | 2px 내려앉음 | 같음 |
| 위험 `.button--danger` | 코랄 채움 + 두께 | 진한 코랄 | 내려앉음 | 같음 |

### 상태 언어

| 상태 | 색 | 색이 아닌 단서 |
| --- | --- | --- |
| hover | 옅은 보라 선 | 1px 들림 + 높이 2 (채우지 않는다 — 고른 것처럼 보이면 안 된다) |
| focus-visible | 진한 보라 고리 (어두운 HUD 안에서는 흰 `--focus-on-hud`) | 3px 고리 + 2px 띄움, 요소 모서리를 따른다. 그림 위에 홀로 뜬 edge HUD 조각(설정·닉네임·캐릭터·랭킹 입구)은 같은 고리를 조각 **안쪽**에 그린다 — 바깥은 하늘·구름·나무라 어떤 색도 대비를 보장하지 못한다 |
| 캐릭터가 올라섬 (`is-standing`) | 초점과 같은 고리 (+ 칸은 옅은 보라) | 초점 고리와 **같은 모양** — 뜻이 같다. 그래서 **한 번에 하나만** 보인다: 키보드 초점이 버튼·링크·입력칸에 보이는 동안에는 다른 요소의 올라섬 고리·선·바탕을 거둔다(Enter 는 초점 쪽을 누른다). 걷기 시작하면 초점이 풀려 돌아온다. 보기·바닥 칸의 캐릭터 위치 불과 앉은 좌석·고른 캐릭터는 상태라 남는다 |
| 눌림 | — | 두께·그림자 사라짐 + 1–2px 내려앉음 |
| 손가락 선택 버튼: 누르는 중 (`.walk-confirm--pressed`) | 진한 보라 | 2px 내려앉음 — 뗄 때 확정하므로 밖으로 빼면 다시 솟아 «취소»를 미리 보인다 |
| 손가락 선택 버튼: 누를 대상 없음 (`[data-armed='false']`) | 반투명 흰 바탕·흐린 글자 | 보라 채움 원 → 빈 고리, 눌림 두께 없음 |
| 선택됨 (캐릭터·내 기록·내 순위·고른 탭) | 옅은 보라 | ✓ 배지 / 왼쪽 띠·«방금 등록» 배지 / 흰 표면으로 들린 탭 |
| 꺼짐 | 회색 | 그림자·두께 없음, 흐린 글자, 금지 커서 |
| 캐릭터 위치 (보기·칸) | 보라 채움 | 번호 칸까지 채워진 «불 켜짐» |
| 정답 | 민트 | ✓ 알약 «정답», 채운 번호 칸, 무대 칸 ✓ |
| 오답 | 코랄 | ✗ 알약 «오답»/«내 답», 흔들림, 무대 칸 ✗ |
| 시간 초과 | 코랄 시트 | ✗ 배지 + «시간 초과입니다» + «내 답 · 고르지 않음» 줄, 무대에는 정답 칸만 ✓ |
| 피드백 정답 줄 (오답·시간 초과) | 민트·코랄 옅은 라벨 | «정답» ✓ 라벨 + 굵은 «N번 · 보기» / «내 답» ✗ 라벨 + 보조 글. 맞으면 줄을 접는다 |
| 제출 대기 (온라인) | 골드 | **점선** 테두리 + ⧗ 알약 «제출됨» |
| 남은 5초 | 코랄 (어두운 HUD 위 `--hud-warning`) | 시계 → 경고 아이콘, «N초 남았어요», 글자·막대·HUD 선이 함께 바뀐다. 깜빡이지 않는다 |
| 문항 시간 제한 없음 (로컬, FR-3.7) | — | 막대를 거두고 시계 옆 «시간 제한 없음»만 쓴다(`.timer--unlimited`). 남은 5초 경고가 없다 |
| 설정 토글 켜짐 / 꺼짐 | 옅은 보라 상태 칸 / 트랙 회색 칸 | ✓ «켜짐» / «꺼짐» 글자, 켜짐은 보라 선. 이름(소리·움직임 줄이기)은 바뀌지 않고 `aria-pressed` 가 낭독한다 |
| 문항 시간 고른 칸 | 보라 글자 | 트랙 위로 흰 표면이 들리고(높이 1) ✓ 를 단다 — 랭킹 탭과 같은 분절 묶음 |
| 준비 (대기실) | 민트 | ✓ «준비 취소» 토글, 준비판 ○ → ✓ (방장은 시작 요청이 곧 준비라 늘 ✓) |
| 연결 끊김 (대기실) | 골드 | **점선** 준비판 + 경고 아이콘 «연결 끊김»(한 줄, 좁힌 여백과 12px 표식으로 80px 액자 칸 안), 흐린 액자, 바닥 캐릭터 숨김 |
| 게임 중 (로비 방 줄) | 골드 | ⧗ «게임 중» 배지 + 잠긴 «끝나면 참가» |
| 요청 중 (온라인 입구·제출) | — | `aria-busy` + 잠김, «연결 중…»·«참가하는 중…»·«만드는 중…» 글자 |
| 옮기는 중 (결과의 「대기실로」) | — | `aria-busy` + «연결 중…» 글자, 진행 커서. 잠그지 않는다 — 다른 행동을 누르면 그쪽이 이긴다 |

### 화면별 패턴

- **홈** — 월드가 전체 viewport다. 닉네임·설정·캐릭터·랭킹은 가장자리의 독립 HUD 슬롯이며,
  브랜드는 중앙 탑 위에만 뜬다. 그 아래 부제 `4지선다 상식 퀴즈 · 혼자·친구와`는 말 덩어리 둘을 줄 바꿈 없이 묶어
  넓은 화면에서 한 줄(최대 240px, 브랜드 아래 가운데)로 읽히고, 좁으면 «·» 곁에서만 나뉜다(폭 420px 이하에서는
  부제만 접고, 높이 700px 이하에서는 브랜드째 시각적으로 접는다 — 다만 높이 420px 이하·폭 640px 이상의 가로 휴대폰은
  브랜드만 24px로 위 가운데에 되살린다). 닉네임 값 위에는 작은 `닉네임` 라벨을 둔다. 다섯 분야는 하단 dock 한 줄,
  게임의 두 직접 진입점인 **온라인·전체 도전은 같은 크기의 큰 CTA**로 둔다. 폭 560px 이하는 기본 한 열이며,
  높이 480px 이하에서는 전체 최고점 pill을 시각적으로 접고 접근 가능한 이름에 남긴다. 그중 폭 421–560px만
  같은 폭의 두 열을 유지하고, 폭 420px 이하는 높이와 관계없이 한 열이다. 폭 560px을 넘으면 두 열로 둔다.
  dock 높이는 `ResizeObserver`가 `--home-dock-h`로 전달해 최고 점수가 생겨도 touch 조작부가 바로 위를
  따른다. 분야 최고점은 별+숫자로 보이고, 전체 최고점은 공간이 충분할 때 CTA의 `최고 N점`으로 보이며
  화면 크기와 관계없이 접근 가능한 이름에 남는다. 온라인 CTA는 이름 아래 `친구와 함께 · 2명부터` 보조 줄을
  보이고(아이콘 칸 높이 안이라 전체 도전과 크기가 같다), 로비를 불러오는 동안 같은 자리에 `연결 중…`을 띄운다.
  아직 들어가 있는 방이 있으면 dock 맨 위에 안내 알림 줄 모양의 복귀 버튼(`「방 이름」 방에 아직 있어요` + 밑줄 친 `돌아가기`)을 둔다.
  높이 420px 이하·폭 640px 이상의 가로 휴대폰(U07)은 dock을 «분야 다섯 칸 | 온라인·전체 도전» 한 줄로 낮춘다(740×360에서
  171px → 69px). 분야 칸은 짧은 이름, 두 CTA는 같은 두 칸(아이콘 28px)이고 전체 최고점 pill은 접어 이름에 남긴다. 복귀 줄은
  그 한 줄 위에 폭을 다 쓴다.
  캐릭터는 「내 캐릭터」 입구 바로 아래 월드 바닥에서 시작한다. 높이 700px 이하에서는 dock 위 양쪽으로 내려온 두 입구 사이
  가운데의 빈 하늘(브랜드가 보이면 그 아래)에서 시작한다.
- **퀴즈(로컬·온라인)** — HUD 한 블록(분야 칩 · 픽셀 위치 숫자 · 옅은 진행률 · ? · 나가기 / 시계 · 남은 시간 ·
  굵은 타이머) → 질문 overlay → 같은 모양의 보기 넷(넓은 화면은 늘 2×2, 좁은 화면은 한 줄에 하나이되 넷이 모두
  12자 이하면 2×2 — 그때 판정 알약은 ✓ ✗ ⧗ 모양만 보이고 글은 낭독용으로 남는다) → 월드가 비치는 arena. touch 기기의 높이 480px
  이하 가로 화면(U15)은 두 열이다 — 왼쪽 열에 HUD·질문·보기, 오른쪽 열 아래쪽에 arena(바닥 칸은 열 폭만큼의 정사각, 64–104px).
  양옆 여백이 고정 스틱·선택(과 위 끝의 설정 버튼) 자리라 답하기 전에 스크롤 없이 넷과 네 칸이 보이고 조작부가 그 위에 오지
  않는다. 좁은 열이라 질문은 18px, 보기는 안쪽 여백 8px·판정 알약은 모양만(높이는 44px 이상). 로컬 남은 시간은 그 판의 문항 시간
  (20초·40초)에서 줄고, «제한 없음» 판은 막대를 거두고 «시간 제한 없음»만 쓴다. 질문 제목은 숨긴 설명으로
  «문항당 N초»·«시간 제한 없음»을 함께 읽힌다. 로컬 전체 도전의 분야 칩은 문항마다
  `전체 도전 · 분야`이고 분야 색은 칠하지 않는다. 로컬 피드백은 arena 뒤 문서 흐름의 결과 패널(판정 → 틀렸을 때의
  정답 줄 → 해설 → 다음 문제)로 이어지고, 질문 머리를 화면에 남기는 만큼만 자동 스크롤한다. 둘이 한 화면에 들지
  않을 때만 패널 끝에 맞춘다(짧은 가로 두 열은 늘 이쪽이라, 판정·정답 줄·다음 문제가 패널 안 스크롤 없이 한 화면에 들도록
  패널 높이 한도가 화면 높이 − 24px이다). 고정 offset을 쓰지 않아 최장 질문·해설과 짧은 viewport에서도 보기·네 칸·
  패널이 서로 덮이지 않는다. fixed 캐릭터 발의 arena 내부 상대 좌표를 전후에 복원해 결과 칸과 표정을 유지한다. 온라인 결과 공개는
  같은 배지·테두리와 «정답 / 내 답» 줄을 쓰고, arena 바로 뒤(상태 줄·채팅 앞) 문서 흐름의 카드로 처음 공개될 때 한 번
  보이는 데까지 옮긴다. 온라인 HUD의 남은 시간은 서버가 보낸 남은 양으로 **표시만** 하며(«N초 남았어요», 남은 5초 경고,
  0초에는 «결과를 기다리는 중…»), 공개 중에는 «다음 문제까지 N초»를 보인다. 온라인 최종 순위는 동점을 «공동 N위»로 쓴다.
- **결과** — 점수 장면(분야 칩, 48px 픽셀 점수, 픽셀 등급, 굵은 등급 안내, 최고 기록 칩 — 신기록·첫 기록은 골드 별, 뒤에는 방사형 scrim) →
  요약 칩 셋(✓ 정답 / ◎ 정답률 / 시계 소요 시간) → (오답이 있으면) `틀린 문제 N개 해설 보기` 글자 링크 →
  **다시 하기**(한 줄 전체) → 랭킹·홈·대기실(보조, 한 줄) → 랭킹 등록 패널(랭킹과 같은 저장 범위 안내 줄:
  «화면을 나가면 이 이름으로 저장돼요 · 이 브라우저에만 저장돼요») → 오답 복습 패널(줄 사이 1px 선, 내 답 ✗·정답 ✓ 알약).
  링크는 버튼이 아니라 밑줄 친 글자(44px 목표, 유리 바탕)이고 누르면 주소를 바꾸지 않고 복습 제목으로 포커스를 옮긴다.
  캐릭터는 점수 장면 왼쪽 위 빈자리에서 시작하므로 축하 별은 오른쪽 위에만 둔다. 최고 기록 칩은 첫 화면에서 한 줄로 읽히는 짧은 상태만 쓴다.
- **랭킹** — 저장 범위 안내 줄 → 분절 탭(3×2) → 패널 하나의 순위 줄(금·은·동 칸, 내 기록은 보라 바탕·왼쪽 띠·배지) →
  위험 보조 버튼. 빈 탭은 설명으로 막지 않고 `{탭 이름} 시작하기`(예: `과학 시작하기`)로 그 탭의 판을 곧바로 연다.
  문제를 불러오지 못해 그 판을 열 수 없으면(홈에서 그 분야 칸이 잠긴 것과 같은 규칙) `홈으로`가 된다.
  위험 보조 버튼은 모든 랭킹을 지우므로 **어느 탭에도** 기록이 없을 때만 숨기고, 지운 뒤에는 포커스를 빈 탭의 시작 행동으로
  옮긴다. 360px 이하의 짧은 화면에서는 위험 보조 버튼을 줄여 양쪽 고정 조작부와 닿지 않게 한다. 안내 배너가 머리말 바로 뒤에 오는 온라인·랭킹 화면은 워커를
  머리말 오른쪽 아래에 세우고 글 끝에 캐릭터 폭만큼 여유를 둬 320px에서도 글자를 덮지 않는다.
- **내 캐릭터** — 월드가 비치는 3열(넓으면 4열) pedestal, 그림 아래 받침 그림자, 고른 칸은 보라 + ✓ 배지.
- **온라인 로비** — edge HUD 머리(제목·돌아가기·안내) → 세 동작 분절 묶음(어두운 바. 쉬는 칸은 바탕 없는 흰 아이콘,
  hover 는 보라 선만, 고른 칸은 금빛 선·채움과 보라 아이콘 칸, 올라섬은 흰 고리) → 상황별 방 목록 overlay
  (줄마다 분야 아이콘 칸·공개/🔒 잠김 배지·⧗ 게임 중 배지·행동) / 코드 참가 / 방 만들기 폼(`최대 인원` 아래
  `2명부터 시작할 수 있어요` 도움말 — 입력칸과 같은 선에서 시작하고, 라벨이 위로 올라가는 380px 이하에서는 들이지
  않는다). 빈 목록은 `방 만들고 친구 부르기`와 보조 `혼자 연습하기`, 목록을 못 받으면 `다시 시도`만 둔다. 다시 시도가
  통하거나 필터를 풀어 빈 칸이 접히면 포커스는 나타난 목록의 첫 버튼으로 간다. 420px 이하 또는 480px 이하의 짧은
  화면에서는 제목과 동작 이름만 남겨 소개 문구를 반복하지 않고, 세 동작을 56px 가로형 분절 버튼으로 압축한다.
  짧은 화면에서 조작부와 겹치는 방 개수 status는 시각적으로만 접고 낭독은 유지한다. 높이 480px 이하의 스크롤
  화면에서는 설정 버튼도 문서와 함께 흘려, 아래에서 올라온 필터·새로고침 같은 동작을 덮지 않는다. 스크롤 없는 홈은
  고정 edge HUD를 유지한다.
- **대기실** — 제목·나가기 → 방 코드 칩(시스템 글꼴 굵은 글자)·인원 글·「초대 링크 복사」 → 도는 설정 칸
  둘(오른쪽 ↻ 표식, 방장이 아니면 거둔다) → 준비 토글(참가자만) → 시작(방장만) → 시작 상태 줄(유리 표면,
  꺼진 시작의 이유·기다리는 사람) → 세계 방(벽 액자·바닥 가구, 세계 장식) → 채팅(채팅칸·안내·로그가 선과 모서리를 나눠 가진 유리 표면 하나).
- **온라인 퀴즈** — 로컬 퀴즈와 같은 HUD·질문·보기·arena 뒤에 매치 상태 줄과 채팅이 각각 유리 표면에 얹힌다.
- **대화상자** — 가운데 카드(높이 3), 화면보다 길면 배경 안에서 스크롤해 제목이 잘리지 않는다.
- **설정** — 앱 바의 톱니(`gear`) 하나가 어느 화면에서나 연다. 제목 → 소리 토글(한 줄 버튼, 오른쪽 켜짐/꺼짐 칸) →
  문항 시간(20초·40초·제한 없음 세 칸 분절 묶음, «기본은 20초 · 새 판부터 · 온라인은 20초 고정» 도움말) →
  움직임 줄이기 토글(도움말) → 닫기. 고르는 순간 적용되고 «저장» 단계가 없다. `select` 를 쓰지 않는다.

## 8. 접근성

- 손가락 목표 44px: 버튼·보기·분야 칸·dock 칸·탭·입력칸·설정 칸·캐릭터 칸·좌석·조작법·앱 바 설정 버튼·설정 대화상자의 토글과 문항 시간 칸.
- 초점 고리는 키보드 이동에만(`:focus-visible`) 보이고, 캐릭터가 올라선 표시와 같은 모양이다. 어두운 HUD에서는
  `--focus-on-hud`로 3:1을 지키고, 초점이 보이는 동안 다른 곳의 올라섬 표시는 숨어 Enter 대상이 늘 하나다.
- 아이콘·장식은 `aria-hidden`. 앱 바의 설정 버튼은 아이콘만 보이지만 이름 «설정»이 낭독된다. 설정 안의 소리·움직임 줄이기
  토글은 **이름이 고정**이고 켜짐/꺼짐은 `aria-pressed` 만 말한다(U54) — 이름까지 «소리 꺼짐»으로 바꾸면 «소리 꺼짐, 눌리지
  않음»처럼 부정이 겹쳐 읽힌다. 눈으로 보는 켜짐/꺼짐 글은 `aria-hidden` 이다. 소리를 켜면 짧은 확인음이 난다.
- 라이브 리전과 일반 화면 전환 포커스 계약은 유지한다. 긴 조작법 대화상자는 읽기 시작점인 패널에
  먼저 포커스를 두고, Tab·Shift+Tab은 닫기 버튼 안에서 순환한 뒤 Escape로 열었던 자리로 돌아간다.
- 색에만 기대지 않는다 — §6 상태 언어 표의 오른쪽 열이 그 증거다.

## 9. 하지 말 것

- 카드마다 굵은 하단 그림자·이중 테두리·가짜 창 점·회전 장식을 넣지 않는다.
- 분야 색으로 카드를 통째로 칠하지 않는다 (무지개 홈).
- 픽셀 글꼴을 본문·설명·버튼에 쓰지 않는다.
- 글리프를 아이콘으로 쓰지 않는다. 새 아이콘은 묶음에 더한다.
- `z-index` 를 주지 않는다 (DOM 순서가 겹침 순서다). 앱 바는 `main` 뒤, 피드백·dialog 앞에 두어
  월드보다 위이고 modal보다 아래인 순서를 마크업으로 보장한다. 같은 이유로 걷는 캐릭터(`fixed`)보다
  뒤에 오는 문서 흐름 표면(온라인 공개 카드·상태 줄·채팅)에는 `position` 을 주지 않는다 — 캐릭터를 덮는다.
- 여러 화면을 오가는 고정 bottom navigation을 두지 않는다. 홈의 분야 dock은 홈 월드 안의 목적지이며,
  손가락 조작부를 바로 위 양 모서리에 배치해 서로 겹치지 않는다.
- 끝없이 반복되는 화면 애니메이션을 두지 않는다.
- 레벨·재화·업적·힌트 수처럼 제품에 없는 값을 그리지 않는다.
