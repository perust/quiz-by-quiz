## 1. 개요

### 1.1 목적
브라우저에서 바로 실행되는 4지선다 상식 퀴즈 게임을 만든다. 사용자는 카테고리를 골라 문제를 풀고, 매 문항마다 정답 여부를 즉시 확인하며, 마지막에 점수와 순위를 기록한다.

### 1.2 배경
짧은 시간(3~5분) 안에 끝나는 가벼운 퀴즈 경험을 목표로 한다. 회원가입이나 서버 없이도 완결된 플레이가 가능해야 하며, 점수 기록을 통해 반복 플레이 동기를 만든다.

### 1.3 타깃 사용자
- 자투리 시간에 가볍게 퀴즈를 풀고 싶은 일반 사용자
- 자신의 이전 점수와 비교하며 반복 도전하는 사용자

## 2. 목표 및 성공 기준

| 목표 | 성공 기준 |
| --- | --- |
| 한 판을 끊김 없이 완주 | 카테고리 선택부터 결과 화면까지 이탈 없이 도달 |
| 즉각적인 피드백 | 선택 후 300ms 이내에 정답/오답 표시 |
| 반복 플레이 유도 | 결과 화면에서 "다시 하기" 진입률 확보 |
| 기록 보존 | 새로고침·브라우저 재실행 후에도 랭킹 유지 |

### 2.1 설계 원칙
**충분히 생각할 시간을 보장한다.** 상식 퀴즈의 순기능은 문제를 곱씹고 해설을 읽으며 알게 되는 데 있다. 속도를 점수로 보상하는 장치는 도입하지 않으며, 제한 시간은 경쟁 요소가 아니라 한 판의 길이를 예측 가능하게 만들기 위한 장치로만 둔다. 기능 추가 시 이 원칙과 충돌하는지 먼저 확인한다.

## 3. 범위

### 3.1 v1 포함
- 4지선다 객관식 퀴즈 진행
- 카테고리 5종: 한국사 / 과학 / 지리 / 일반상식 / 예술과문화
- 카테고리별 10문제 이상이며 서로 같은 수를 유지하는 확장형 문제 은행
- 정답/오답 즉시 피드백 + 해설 표시
- 점수 계산 및 결과 화면
- 랭킹(순위) 기록 및 조회
- 반응형 UI (모바일 우선)

### 3.2 후속 로드맵
아래 방향을 위해 교체·확장 가능한 구조를 유지한다.

- **문제 은행 확장** — 균형과 품질 검증을 유지하며 지속적으로 문제를 추가한다. → FR-1.2, FR-1.3
- **서버 기반 전체 사용자 랭킹** — 온라인 방의 서버 채점 점수로 기록한다(v1.3에서 방향 확정, 기록·랭킹 화면·기록 내보내기 구현). → FR-6.8, FR-7.13 2단계
- **온라인 전용 전환** — 혼자 하기를 없애고 온라인 혼자 판으로 옮긴다(3단계는 PR — 소유자 결정 네 가지가 정해졌고, 배포 뒤 병합한다). → FR-7.13

### 3.3 v1 제외 (미정)
- 로그인 / 계정 시스템
- 문제 추가·수정 관리자 화면
- ~~멀티플레이 / 실시간 대결~~ → 온라인 방으로 구현해 FR-7에 편입(v1.3)
- 즐겨찾기, 오답 노트

## 4. 사용자 흐름

```
[홈]
  └─ 카테고리 선택 ──┬─ 단일 카테고리 (10문제)
                    └─ 전체 도전 (25문제, 카테고리당 5문제)
         │  (FR-7.13 3단계: 혼자 푸는 온라인 판으로 곧바로 연다 — 서버가 채점·기록, 결과는 온라인 결과 화면.
         │   다른 분야의 혼자 판이 돌고 있으면 그 판을 기록 없이 끝내고 연다(10.1 #11). 서버에 닿지 않으면
         │   아래 로컬 흐름을 «연습(기록 안 남음)»으로 연다. 이 기능을 모르는 API면 아래 그대로)
         ▼
[퀴즈 진행] ── 문제 표시 → 보기 선택 → 즉시 피드백(정답/오답 + 해설) → 다음 문제
         │                                                              │
         │◄─────────────────────── 마지막 문제까지 반복 ─────────────────┘
         ├─ (중간에 나가기) ── 홈 / 푼 문제 다시 보기(기록 없음) → 홈
         ▼
[결과] ── 점수 / 정답 개수 / 소요 시간 / 오답 목록
         ├─ 닉네임 확인 → 랭킹 등록 (등록하지 않고 떠나도 자동 등록)
         ├─ 다시 하기
         └─ 랭킹 보기
         │
         ▼
[랭킹] ── 모드·카테고리별 상위 기록 목록
```

## 5. 기능 요구사항

### FR-1. 문제 은행
| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-1.1 | 카테고리 5종이 각각 10문제 이상을 보유하고 카테고리별 은행 크기를 같게 유지한다 | 필수 |
| FR-1.2 | 한 판의 출제 문항 수는 은행 크기와 분리된 상수로 관리한다 (카테고리 모드: 10문항). 은행이 커져도 코드 수정 없이 문항 수가 유지된다 | 필수 |
| FR-1.3 | 은행의 문제 수가 출제 문항 수보다 많으면 무작위 표본을 추출한다 | 필수 |
| FR-1.4 | 직전 판에 출제된 문제는 다음 판 표본 추출에서 후순위로 밀어 중복 체감을 줄인다 | 권장 |
| FR-1.5 | 각 문제는 질문, 보기 4개, 정답 인덱스, 해설을 포함한다 | 필수 |
| FR-1.6 | 문제 데이터는 코드와 분리해 카테고리별 JSON 파일로 관리한다 (`data/history.json` 등) | 필수 |
| FR-1.7 | 문제 출제 순서와 보기 4개의 표시 순서를 매 판마다 섞는다 | 필수 |
| FR-1.8 | 문제 ID는 고유하며, 문제 추가 시 기존 ID를 재사용하지 않는다 | 필수 |
| FR-1.9 | 앱 시작 시 문제 데이터의 형식 오류(보기 개수 불일치, 정답 인덱스 범위 초과 등)를 검사하고, 불량 문제는 출제에서 제외한다 | 권장 |
| FR-1.10 | 한 판의 난이도 구성은 그 분야 은행의 난이도 비율을 따른다. 문항 수 × 비율을 최대 나머지 방식으로 정수로 나누고(나머지가 같으면 무작위), FR-1.4(안 본 문제 먼저, 다음은 오래전에 본 것부터) 안에서만 맞춘다. 전체 도전은 분야마다 5문제를 지키면서 판 전체가 비율을 따른다(판의 목표는 분야마다의 몫의 합). 난이도가 없거나 규정 밖인 문제는 한 묶음으로 본다. 온라인 매치도 같다 | 권장 |

> **확장 시 주의**: 은행이 출제 수보다 커서 판마다 문제 세트가 달라진다. 랭킹의 완전한 동일 조건 비교가 필요하면 "고정 세트 챌린지 모드"를 별도로 도입한다.
>
> **FR-1.10 추가 (N05)**: 출제가 난이도를 보지 않아, 은행의 26%가 어려운 문제인데도 10문제 판에 어려운 문제가 넷 이상 나오는 일이 네 판에 한 번꼴(약 23–25%)이었다. 판마다 체감 난이도가 크게 흔들리면 점수를 서로 견주기 어렵다(FR-5.7). 이제 한 판은 은행의 비율을 따른다 — 지금 은행이면 분야 판은 쉬움 3~4·보통 4·어려움 2~3, 전체 도전은 쉬움 9·보통 9·어려움 7이다. 전체 도전을 분야마다 따로 나누면 다섯 분야 모두 어려움이 하나로 내림돼 어려움이 늘 5개(20%)가 되어, 같은 키에 쌓이는 전체 도전 랭킹에서 예전 판(무작위, 평균 6.5개)보다 늘 쉬운 판이 된다 — 그래서 판 전체로 나누고, 분야마다는 제 비율에서 난이도별로 하나 넘게 벗어나지 않게 한다. 다만 **중복 회피(FR-1.4)가 먼저다**: 한 난이도의 안 본 문제가 모자라면 다른 난이도의 안 본 문제로 채우고, 난이도를 맞추려고 본 문제를 내지 않는다. 출제 수(FR-1.2)와 출제 순서 섞기(FR-1.7)는 그대로이고, 점수에 난이도 배점을 두지 않는다(10.1 #4).

### FR-3. 퀴즈 진행
| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-3.1 | 한 화면에 한 문제만 표시한다 | 필수 |
| FR-3.2 | 현재 진행률(예: 3/10)과 진행 바를 표시한다 | 필수 |
| FR-3.3 | 보기를 선택하면 즉시 확정되며, 같은 문제를 다시 풀 수 없다 | 필수 |
| FR-3.4 | 이전 문제로 돌아갈 수 없다 | 필수 |
| FR-3.5 | 키보드 1~4 키로 보기를 선택할 수 있다 | 권장 |
| FR-3.6 | 진행 중 나가기 시 확인 후 홈으로 이동하며, 해당 판은 기록되지 않는다. 브라우저 뒤로 가기도 같은 확인을 거친다. 한 문제라도 풀었으면 확인 창에서 «나가고 푼 문제 해설 보기»를 골라, 기록하지 않은 채 푼 문제를 정답·해설과 함께 볼 수 있다. 마지막 문제까지 답했으면 그 자리는 «결과 보기»이고 결과 화면으로 가 기록이 남는다 | 필수 |
| FR-3.7 | 문항당 제한 시간은 기본 20초이며, 남은 시간을 시각적으로 표시한다. 로컬 판은 설정에서 20초(기본)·40초·제한 없음 가운데 고를 수 있고 새로 여는 판부터 적용한다. 제한 없음이면 시간 초과가 없고 «시간 제한 없음»을 표시한다. 혼자 푸는 온라인 판도 같은 설정을 쓴다(제한 없음 포함, 10.1 #9). 친구와 푸는 온라인 매치는 방장이 방마다 20초(기본)나 40초를 고른다(제한 없음은 없다) | 필수 |
| FR-3.8 | 타이머는 문제가 화면에 표시된 시점에 시작하고, 보기를 선택하는 순간 정지한다. 피드백·해설 화면에서는 흐르지 않는다 | 필수 |
| FR-3.9 | 남은 시간 5초부터 경고 상태로 전환한다. 색상 변화와 함께 숫자·아이콘 등 색각과 무관한 신호를 병행한다 (제한 없음에는 경고가 없다) | 필수 |
| FR-3.10 | 제한 시간 안에 선택하지 않으면 시간 초과로 오답 처리하고, 일반 오답과 동일하게 정답과 해설을 표시한다. 자동으로 다음 문제로 넘어가지 않는다 | 필수 |
| FR-3.11 | 타이머는 시작 시각 기준(경과 시간 계산) 방식으로 구현해, 탭 전환이나 브라우저 스로틀링으로 시간이 어긋나지 않게 한다 | 필수 |
| FR-3.12 | 일시정지 기능은 제공하지 않는다 | 필수 |

> **FR-3.6 추가 (N04)**: 25문제 전체 도전의 24번에서 나가면 남는 것이 하나도 없었다. 이제 나가기 확인이 «나가고 푼 문제 N개 해설 보기»를 함께 주고, 고르면 판을 나가기와 똑같이 끝낸 뒤 푼 문제를 결과의 오답 풀이와 같은 모양(맞힌 문제는 «내 답 · 정답» 한 줄, 전체 도전은 분야별 묶음, 문제마다 신고 링크 FR-5.8)으로 보인다. **결과 화면이 아니다** — 끝까지 풀지 않은 판이라 점수·등급·최고 기록 비교(FR-5.7)·랭킹 등록(FR-6.1의 자동 등록 포함)이 없고 최고 점수(FR-2.3)에도 들어가지 않는다. 그 화면을 떠나는 곳은 나가기와 같다. 마지막 문제까지 답한 판은 끝까지 푼 판이라 이 길로 보내지 않는다 — 확인 창의 그 자리가 «결과 보기»가 되어 결과 화면(기록·전체 풀이)으로 간다.
>
> **FR-3.7 변경 (v1.2)**: 예전에는 문항당 20초로 고정이라, 읽는 속도가 느리거나 스크린리더로 문제와 보기 넷을 듣는 데만 10~15초가 걸리는 사람에게는 «충분히 생각할 시간을 보장한다»(2.1)가 지켜지지 않았다. 소유자 승인으로 로컬 판에 20초(기본)·40초·제한 없음을 두고, 앱 바의 「설정」 대화상자에서 고르게 했다(소리·움직임 줄이기와 함께). FR-3.12(일시정지 없음)는 그대로다 — 판 도중에 바꿔도 다음 판부터 쓴다. 점수에 속도가 없어(FR-5.1, FR-6.3) 고른 시간으로 랭킹을 나누지 않고, 기본이 아닌 판의 기록에만 `timeLimitMs`를 남긴다(6.2). 온라인 매치는 여럿이 같은 시계를 쓰므로 개인 설정을 따르지 않는다.
>
> **FR-3.7 온라인 (v1.2, 소유자 결정)**: 처음에는 온라인 매치를 서버의 20초로 고정했다. 이제 방장이 방마다 20초(기본)나 40초를 고른다 — 방 만들기 폼과 대기실의 «문항 시간» 설정 칸(분야·인원처럼 누르면 도는 버튼, 방장만 바꾸고 모두에게 보인다)에서 정하고, 판이 도는 동안에는 바꿀 수 없다. 판을 열 때 그 값이 판에 옮겨 적혀 모든 문항의 마감·시간 초과 기록이 같은 값을 쓰고, 마감은 여전히 서버가 판정한다. **제한 없음은 두지 않는다** — 한 사람이 답하지 않으면 방 전체가 마감까지 멈춘다. 정답 공개(8초)와 «모두 답하면 바로 공개»는 그대로다. 혼자 푸는 온라인 판(FR-7.13 3단계)은 기다릴 사람이 없어 설정의 «제한 없음»도 받는다(10.1 #9) — 로컬 «제한 없음»과 같은 규칙으로, 마감이 없고 직접 낸 답만 답이며 막대·남은 5초 경고가 없다.

> 3단계 전에 함께 정할 것: 혼자 하기의 «제한 없음» 문항 시간(FR-3.7)을 온라인 혼자 방에서도 줄지, 서버가 없는 개발·시연 환경을 어떻게 둘지. → 소유자가 정했다(2026-10-28, 10.1 #8·#9): 혼자 판도 «제한 없음»을 주고(친구와 푸는 방은 20·40초 그대로), 서버가 없거나 닿지 않으면 연습으로 연다. 서버가 없는 개발·시연 화면(`quiz-api-base` 없음)도 연습이다.

> **3단계 구현 (PR — 소유자 결정 반영, migration 013 → API → Pages 배포 뒤 병합)**: 홈의 분야 칸·전체 도전은 대기실을 거치지 않고 혼자 온라인 판을 곧바로 연다(`POST /v1/solo`). 그 사람의 혼자 방(migration 013의 `solo_rooms` 표시, 사람마다 하나)을 다시 쓰고 판을 연다 — 혼자 방은 남의 로비 목록·코드 조회에 없고 남이 들어오지 못한다. 판의 출제·채점·마감·기록은 친구와 푸는 방과 같고(2단계의 기록 그대로), 나가기·브라우저 뒤로·탭 닫기·다시 연결도 오늘의 온라인 규칙 그대로다(판은 서버에서 계속되고 홈의 «이어 풀기»로 돌아온다). 결과는 온라인 결과 화면이고 «다시 하기»(같은 혼자 방의 새 판)·«홈으로»(혼자 방을 나가 지운다)·최고 기록 비교(FR-5.7, 서버가 이 판을 빼고 센 내 최고 점수)를 준다. 홈의 별 점수는 서버의 내 판마다 최고 기록이다(`GET /v1/rankings/mine`, 주인 열쇠 — 신분은 싣지 않는다). 랭킹은 온라인부터 열고 이 브라우저의 기록은 «이 브라우저의 예전 기록»(읽기만)이다. 기록 내보내기(N02)는 온라인 범위에서 내 서버 기록(`GET /v1/rankings/mine/records`, 최근 500개)을 같은 파일 모양으로 내보내고, 예전 기록의 내보내기도 남는다. 새 기능은 세션 응답의 `soloPlay: true`로만 알아서, 이 기능을 모르는 API와 함께 돌면 홈은 예전 혼자 하기 그대로다 — 세션을 열지 못해(요청 한도·규칙 전에 지은 닉네임) 그 API가 아는지 모를 때도 예전 혼자 하기다. 혼자 판의 문항 시간은 설정의 20초·40초·«제한 없음»이다(10.1 #9) — «제한 없음»은 마감 없는 판(서버의 문항 시간 null)이라 시간 초과·발밑 칸 답이 없고 그 사람이 답을 낼 때 공개하며, 화면은 로컬 «제한 없음»처럼 막대와 남은 5초 경고를 거두고 직접 내라고 말한다. 세션 응답의 `soloUntimed: true`를 본 뒤에만 null을 보낸다. 30분 넘게 아무도 보이지 않는 마감 없는 판은 서버의 멤버 정리가 기록 없이 끝낸다. 풀던 혼자 판이 아직 돌 때 같은 분야를 고르면 그 판을 잇고, 다른 분야(또는 전체 도전)를 고르면 확인창 없이 그 판을 기록 없이 끝내고 고른 판을 연다(10.1 #11, `POST /v1/solo`의 `restart` — 세션의 `soloRestart`를 본 뒤에만 보낸다). 끝까지 풀지 않은 판은 기록하지 않고(FR-6, N04), 새 판의 화면이 «풀던 «과학» 판은 끝까지 풀지 않아 기록 없이 끝냈어요»를 한 줄로 보이고 낭독한다. 마지막 문항까지 답해 마지막 공개만 남은 판은 끝까지 푼 판이라 기록하고 끝낸다. 그것을 모르는 API면 예전처럼 홈이 그 판의 «이어 풀기»를 보인다. 새 혼자 방은 동시 한도(1,200개, 넘으면 연습)와 주소·프로세스의 시간당 몫 안에서만 만든다 — «홈으로»가 방을 지워 홈에서 고른 판마다 새 방이기 때문이다. 서버 변화(혼자 방 표시·그 권한·내 기록 색인, 혼자 판의 «제한 없음»을 위한 문항 시간·쓴 시간·마감 CHECK와 그 NULL을 혼자 방·그 판에 묶는 생성 열·외래 키)는 migration 013에 있고 2단계의 012는 그대로다 — 2단계(#108)는 제 경계(migration 012 → API → Pages)로 따로 나가고, 3단계는 그 위에서 **migration 013 → API → Pages**로 나간다(release gate `schemaVersion: 13`). 012의 API는 013이 도는 동안에도 돌고, 013의 API는 012 DB 위에서 돌지 않는다(readiness가 닫히고 방 읽기가 실패한다). 한때 아직 올리지 않은 012에 접어 넣었으나, 같은 번호가 두 스키마를 뜻하면 번호만 보는 migrator가 #108의 012 위에서 고친 012를 돌리지 않으므로 013으로 떼었다(`deploy/oracle/README.md` «Fail-closed staging order»).

> **2단계 구현 (서버 랭킹)**: 서버가 판을 닫는 같은 transaction에서 판의 참가자마다 기록 하나를 남긴다 — 서버가 채점한 점수·맞힌 수·문항 수·분야(전체 도전)·문항 시간·그 방에서 보인 닉네임·캐릭터·브라우저 신분·판을 닫은 시각. 판 도중 끊긴 사람도 판의 참가자라 남고(시간 초과로 채운 답 그대로), 같은 판·같은 사람은 한 번이다. 브라우저 신분은 «내 기록» 표시(`isMine`)에만 쓰고 응답에 싣지 않는다 — 신분은 공개되는 id만이 아니라 그 브라우저의 토큰에서 나온 주인 열쇠까지 같아야 내 기록이다(지워진 id를 남이 다시 등록해도 남의 기록을 «나»로 읽지 못한다). 조회는 점수 내림차순, 같은 점수는 먼저 남긴 기록이 위이고 순위는 그 순서(1, 2, 3)다(FR-6.3과 같다). «이번 주»는 서울 시각 월요일 0시부터 다음 월요일 0시 전까지다. 오래된 기록은 최근 8주와 판마다 전체 상위 100만 남기고, 25만 줄을 넘으면 가장 오래된 것부터 줄인다(전체 상위 100은 남는다). 랭킹 화면은 «온라인 랭킹»과 «이 브라우저의 기록»(지금까지의 혼자 하기 랭킹, FR-6.10의 범위 안내 그대로)을 범위 탭으로 나누고, 온라인 결과 화면은 «이 판의 점수가 온라인 랭킹에 기록됐어요»와 그 랭킹으로 가는 길을 준다. 이 기능을 모르는 이전 API와 함께 돌면 화면은 온라인 랭킹을 숨기고, 세션을 열지 못하면(서버에 닿지 않는다, 저장된 닉네임이 규칙에 걸렸다) 처음 화면은 이 브라우저의 기록이다(닉네임 탓이면 «홈으로»가 고칠 곳을 안내한다). 배포 순서는 migration 012 → API → Pages다(`deploy/oracle/README.md`).

## 6. 데이터 모델

### 6.1 문제 (Question)
```json
{
  "id": "history-001",
  "category": "history",
  "question": "훈민정음이 반포된 해는?",
  "choices": ["1443년", "1446년", "1450년", "1392년"],
  "answerIndex": 1,
  "explanation": "1443년에 창제되고 1446년에 반포되었습니다.",
  "difficulty": "easy",
  "tags": ["조선", "세종"]
}
```

`difficulty`(`easy` / `normal` / `hard`)는 한 판의 난이도 구성을 은행 비율에 맞추는 데 쓴다(FR-1.10). 점수에는 쓰지 않는다(FR-5.1). `tags`는 아직 쓰지 않지만, 주제별 필터를 붙일 때 기존 문제를 일괄 수정하지 않도록 처음부터 스키마에 포함한다.

카테고리 코드의 현행 기준은 `src/constants.ts`다. 현재는 `history`(한국사), `science`(과학), `geography`(지리), `general`(일반상식), `art`(예술과문화)를 사용한다.

### 6.2 랭킹 기록 (ScoreRecord)
```json
{
  "id": "uuid",
  "nickname": "홍길동",
  "mode": "category",
  "category": "history",
  "score": 80,
  "correctCount": 8,
  "totalCount": 10,
  "durationMs": 96400,
  "playedAt": "2026-08-04T12:30:00+09:00"
}
```

`mode`는 `category` 또는 `all`. `mode`가 `all`이면 `category`는 `null`.

선택 필드 `timeLimitMs`(v1.2): 기본(20초)이 아닌 판에만 남긴다. `40000`이거나 `null`(제한 없음)이고, 키가 없으면 20초 판이다. 랭킹은 이 값으로 나누지 않는다(FR-3.7). 스키마 버전은 올리지 않는다 — 더하기만 한 필드다.

### 6.3 저장소 키
| 키 | 내용 |
| --- | --- |
| `quiz.rankings` | ScoreRecord 배열 |
| `quiz.settings` | 소리 켜짐 여부, 로컬 판의 문항 시간(`timeLimitMs`: 20000·40000·null), 움직임 줄이기(`reduceMotion`), 고른 캐릭터. 목록 밖의 값은 기본값으로 되돌린다 |
| `quiz.nickname` | 마지막으로 입력한 닉네임 |

## 8. 비기능 요구사항

- **반응형**: 모바일 우선, 320px 폭까지 레이아웃이 깨지지 않을 것
- **성능**: 첫 화면 로딩 1초 이내, 문제 전환 지연 없음
- **오프라인**: 서버에 닿지 않으면 홈이 연습(기록 안 남음)을 연다 — 네트워크 없이도 전체 플레이가 된다(FR-7.13 3단계, 10.1 #8 소유자 결정). 온라인 판·방은 서버가 필요하고, 서버가 다시 답하면 혼자 온라인 판으로 돌아온다
- **접근성**: 보기 버튼 키보드 포커스 이동 가능, 정답/오답을 색상만으로 구분하지 않고 아이콘·텍스트 병행
- **데이터 무결성**: 저장된 랭킹 데이터가 손상된 경우 앱이 죽지 않고 빈 랭킹으로 복구

## 9. 기술 가정

- 프레임워크 없는 TypeScript + HTML + CSS 단일 페이지 구성
- 번들러 없이 `tsc`만 사용해 `src/*.ts`를 `js/*.js`로 컴파일한다. 배포는 GitHub Pages 등 정적 호스팅
- 상태는 메모리에서 관리하고, 랭킹·설정만 localStorage에 영속화
- 문제 데이터는 카테고리별 JSON으로 분리해 정적 로드
- 랭킹은 저장소 어댑터를 거쳐 접근하며, v1 구현체는 localStorage 기반
- 게임 로직(출제·채점·타이머)과 화면 렌더링을 분리해, v2에서 프레임워크 이전 시 로직을 재사용할 수 있게 한다

### 9.1 랭킹 저장소 범위 (중요)

v1 랭킹은 **각 방문자의 브라우저에만 저장된다.** 정적 호스팅에 올려 여러 사람이 접속하더라도 기록은 공유되지 않으며, 닉네임을 입력받아도 그 기록은 입력한 본인 화면에만 보인다. 즉 v1은 **자기 최고 기록 갱신용**이고, 사용자 간 경쟁은 v2에서 DB를 붙여야 성립한다.

이 제약을 v1에서 보완하기 위한 장치:
- 랭킹 화면에 저장 범위를 명시해 오해를 방지한다 (FR-6.10)
- 결과 화면에서 자기 최고 기록과 비교해 재도전 동기를 만든다 (FR-5.7)
- 결과 카드를 이미지·텍스트로 복사해 외부에서 수동으로 비교할 수 있게 한다 (12번 확장 아이디어)

| 10 | 혼자 판의 «홈으로» (옛 10.2 #3, 소유자 결정) | **혼자 방을 지운다(지금 동작 그대로).** 그래서 온라인 출제의 «최근 문제 후순위»(N08, 같은 방의 최근 24판만 본다)도 함께 사라진다 — «다시 하기» 사이에는 FR-1.4가 서지만, 판을 끝내고 홈으로 가서 같은 분야를 다시 고르면 새 방이라 방금 푼 문제가 다시 나올 수 있다(예전 혼자 하기는 이 브라우저의 기록으로 피했다) |
| 11 | 혼자 판이 도는데 다른 판을 고르면 (옛 10.2 #4, 소유자 결정) | **도는 판을 끝내고 고른 판을 새로 연다.** 같은 판(분야·전체 도전)을 고르면 그 판을 잇는다(«이어 풀기»도 그대로). 다른 판이면 확인창 없이 서버가 같은 transaction에서 도는 판을 기록 없이 끝내고(끝까지 풀지 않은 판은 기록하지 않는다 — FR-6, N04) 고른 판을 연다(`POST /v1/solo`의 `restart`, 혼자 판 열기와 같은 요청 한도). 새 판의 화면이 «풀던 «과학» 판은 끝까지 풀지 않아 기록 없이 끝냈어요»를 한 줄로 보이고 낭독한다. 마지막 문항까지 답해 마지막 공개만 남은 판은 끝까지 푼 판이라 기록하고 끝낸다 |

### 12.1 서버 랭킹 정책 (v1.3 확정, 소유자 결정)
| 항목 | 결정 |
| --- | --- |
| 기록 대상 | 모든 온라인 판(혼자 방·여럿 방). 판이 끝날 때 참가자마다 서버가 채점한 점수를 남긴다. 브라우저가 보고하는 점수는 받지 않는다 — 기록 조작 방지는 서버 채점(FR-7.8)으로 푼다 |
| 기록 시각 | 서버가 판을 닫은 시각 |
| 닉네임 | 중복을 허용한다. 욕설·개인정보 모양(전화번호·이메일·주소창 주소 등)은 금칙어 필터로 막는다. 길이는 지금 규칙(2~10자)을 따른다. (구현: 숫자 6개 이상 연속(사이의 기호·공백·«ㅡ»는 이어진 것으로 본다)·`글자@글자`·`://`·`www.`·`이름.com` 같은 주소 끝·짧은 금칙어 목록(흔한 이름·낱말 안에도 있는 말은 따로 선 말일 때만 막는다). 결과 화면의 로컬 등록 이름은 이 브라우저의 기록에만 남고, 규칙에 걸리면 온라인 닉네임이 되지 않는다. 서버가 세션을 열 때 거절하고 홈의 닉네임 대화상자가 같은 규칙으로 먼저 설명한다. 규칙 전에 지은 이름이 걸리면 기록에는 «익명»으로 남긴다) |
| 조회 범위 | 분야(5)·전체 도전별로 «이번 주»와 «전체» 두 기간 |
| 동점 | 먼저 달성한 순(기록 시각 오름차순). 혼자 하기 랭킹(FR-6.3)과 같다 |
| 만점자 변별력 | 주간 랭킹이 매주 새로 시작하는 것으로 푼다. 전체 기간은 초기 만점 기록이 위에 남는다 |
| 기존 로컬 기록 | 서버로 옮기지 않는다(브라우저가 보고한 점수라 믿을 수 없다). 로컬 기록은 이 브라우저의 «내 기록»으로 남는다 — 혼자 하기가 온라인으로 옮긴 뒤(FR-7.13 3단계)에는 «이 브라우저의 예전 기록»으로 읽기만 하고, 지우기·내보내기는 그대로다 |
