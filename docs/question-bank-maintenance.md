# 문제 은행 유지보수 가이드

이 문서는 `data/*.json`에 문제를 추가·수정·검토할 때 따르는 **현행 단일 기준**이다.
초기 제품 범위를 기록한 `docs/quiz-game-claude-code-prompts.md`와 `legacy/` 아래 자료는
역사 자료이며 현재 카테고리 수·출제 수·빌드 방법의 근거로 사용하지 않는다.

## 기준의 우선순위

서로 다른 문서가 어긋나면 다음 순서로 판단한다.

1. `src/constants.ts` — 카테고리와 한 판의 출제 수
2. `src/types.ts`, `src/data/validate.ts` — 브라우저 런타임 스키마
3. 이 문서 — 작성·검토·배포 절차
4. `tools/check_bank.py` — 저장소 전체를 대상으로 하는 자동 검증

문항 수나 다음 ID를 문서에서 추측하지 않는다. 항상 현재 체크아웃에서 검증기를 실행해 확인한다.

```bash
python3 tools/check_bank.py
```

특정 카테고리의 문항을 사람이 읽어야 할 때는 한국어 이름 또는 코드로 좁힐 수 있다.
알 수 없는 카테고리는 전체로 조용히 대체하지 않고 오류로 종료한다.

```bash
python3 tools/check_bank.py --category 과학 --show-questions
python3 tools/check_bank.py --category science --show-questions
python3 tools/check_bank.py --category 과학 --show-similar
```

## 데이터 위치와 스키마

현재 카테고리 정의는 `src/constants.ts`에 있고, 각 코드와 같은 이름의 JSON 파일이
`data/`에 하나씩 있어야 한다. 카테고리를 추가하거나 제거하면 코드와 데이터가 어긋난 상태로
배포되지 않도록 `tools/check_bank.py`가 누락·불명 파일을 실패 처리한다.

문항은 아래 8개 필드를 모두 가진다.

```json
{
  "id": "history-101",
  "category": "history",
  "question": "질문",
  "choices": ["보기 1", "보기 2", "보기 3", "보기 4"],
  "answerIndex": 0,
  "explanation": "정답의 이유를 설명하는 한두 문장.",
  "difficulty": "easy",
  "tags": ["주제"]
}
```

- `id`: `<category>-NNN`. 전역에서 고유하며 삭제된 번호를 다시 쓰지 않는다.
- `category`: 파일명과 같아야 한다.
- `question`: 답이 하나로 결정되는 완결된 질문이다.
- `choices`: 비어 있지 않고 서로 다른 문자열 정확히 4개다.
- `answerIndex`: 정답 보기의 0부터 시작하는 위치다. JSON 불리언은 정수로 인정하지 않는다.
- `explanation`: 정답을 반복하는 대신 이유와 맥락을 1–2문장으로 설명한다.
- `difficulty`: `easy`, `normal`, `hard` 중 하나다.
- `tags`: 비어 있지 않은 문자열 배열이다. 기존 태그를 우선 재사용한다.

JSON은 UTF-8, 공백 2칸 들여쓰기, 한글 원문으로 유지한다. `json.dump`의 기본값처럼
한글을 `\uXXXX`로 바꾸면 검토 diff를 읽기 어려우므로 검증기가 실패한다. 전체 파일을
재직렬화하지 말고 필요한 배열 끝부분만 편집한다.

## 표준 작업 흐름

### 1. 사전 상태 확인

```bash
python3 tools/check_bank.py
```

실패가 하나라도 있으면 새 문제를 더하지 말고 기존 오류를 먼저 해결한다. 경고는 자동 오류가
아니므로 원문을 읽어 사실인지 판정한다.

`/quiz-stats`로 카테고리별 수·난이도·주제 분포를 확인한다. 카테고리 수는 같게 유지한다.
한 카테고리만 늘리는 요청이라면 불균형이 생긴다는 사실을 먼저 밝히고 합의된 범위만 수정한다.
난이도 목표는 `easy 40% / normal 40% / hard 20%`이며 절대 개수가 아니라 현재 비율의
부족분으로 판단한다.

### 2. ID와 범위 결정

- 다음 ID는 해당 카테고리의 **최대 ID + 1**이다.
- 중간에 빈 번호가 있어도 재사용하지 않는다.
- 여러 문항을 추가하면 연속 ID를 예약한다.
- 기존 질문·정답·태그를 검색해 같은 지식을 표현만 바꿔 다시 묻지 않는다.
- `--show-similar` 후보를 읽되, 문장 유사도만으로 중복을 확정하지 않는다.

### 3. 사실 확인 후 초안 작성

- 연도, 수치, 순위, 법률, 과학적 수치처럼 변하거나 오해하기 쉬운 사실은 신뢰할 수 있는
  출처 두 곳 이상에서 교차 확인한다.
- 출처가 충돌하거나 범위가 불명확하면 문항을 넣지 않는다.
- `가장`, `최초`, `유일`, 순위 표현에는 지역·시대·측정 기준을 질문이나 해설에 적는다.
- 현재도 변할 수 있는 사실은 기준 시점을 적거나 변하지 않는 사실로 바꾼다.
- 오답은 같은 종류·시대·단위 안에서 그럴듯하게 만들되 부분적으로도 정답이 되면 안 된다.
- 정답만 유독 길거나 구체적이지 않도록 보기의 문법과 길이를 맞춘다.
- 내부 지식만으로 확신하지 않는다. 확인하지 못한 문제는 추가하지 않는다.

### 4. 편집

대상 `data/<category>.json`만 수정한다. 문제 추가에 애플리케이션 코드 변경은 필요 없다.
기존 정렬과 들여쓰기를 유지하고, `answerIndex`가 실제 정답 위치와 일치하는지 문항마다 다시 읽는다.

`/quiz-daily`처럼 자동으로 한 문항을 추가하는 흐름은 편집 전에 `backups/`에 스냅샷을 만들며,
이 폴더는 `.gitignore`에 포함되어 커밋하지 않는다.

### 5. 자동 검증

```bash
python3 tools/check_bank.py
python3 -m unittest discover -s tests -v
npm ci
npm run check
```

문제 데이터만 바꿨더라도 네 단계를 모두 통과해야 한다. `npm run check`는 파일을 생성하지 않고
TypeScript 타입을 검사한다. `main` 배포 워크플로도 문제 은행 검증을 먼저 실행해야 한다.

자동 검증이 실패 처리하는 것:

- 코드에 선언된 카테고리와 JSON 파일의 일치
- 각 카테고리가 설정된 한 판 출제 수 이상을 보유함
- JSON 파싱, 필수 필드와 타입, ID 형식과 전역 중복
- 보기 수·중복, 정답 인덱스, 난이도, 태그
- 완전히 같은 질문

자동 검증이 **통계와 경고로만 알리는 것**:

- 카테고리 수 균형
- 난이도·정답 위치·정답 길이 분포
- 같은 카테고리 안에서 정답이 같은 문항과 최상급·순위 표현

자동 검증이 판정하지 못하는 것:

- 정답과 해설의 사실성
- 복수 정답 가능성이나 질문의 자연스러움
- 오답의 교육적 품질과 체감 난이도
- 출처의 신뢰성과 최신성

따라서 `통과`는 사람이 읽는 사실·품질 검토를 생략해도 된다는 뜻이 아니다.

### 6. 사람 검토와 diff 확인

- `/quiz-check <카테고리>`: 정답·해설·중복·출처를 검토한다.
- `/quiz-validate <카테고리>`: 최상급·순위·범위 표현을 판정한다.
- `/quiz-range <범위> [카테고리]`: 변경한 ID 범위의 난이도와 보기 편향을 본다.
- `git diff --check`: 공백 오류를 확인한다.
- `git diff -- data/`: 의도한 문항 외의 재직렬화나 순서 변경이 없는지 읽는다.

고치라는 지시가 없는 검토 명령은 파일을 변경하지 않고 제안만 한다.

## 완료 기준

- [ ] 현재 코드에서 읽은 카테고리와 모든 데이터 파일이 일치한다.
- [ ] ID는 최대값 다음 번호이며 전역에서 고유하다.
- [ ] 질문은 하나의 정답만 허용하고 보기 네 개가 모두 성립한다.
- [ ] 정답과 해설을 신뢰할 수 있는 출처로 확인했다.
- [ ] 최상급·수치·순위에는 범위와 기준 시점이 있다.
- [ ] 기존 문항과 질문·정답·주제가 겹치지 않는다.
- [ ] 카테고리 수와 목표 난이도 비율을 악화시키지 않는다.
- [ ] 자동 검증, 단위 테스트, TypeScript 검사를 모두 통과했다.
- [ ] diff에 대상 문항 외의 변경이 없다.
- [ ] PR 본문에 추가 문항 범위, 사실 확인 근거, 실행한 검증을 기록했다.
