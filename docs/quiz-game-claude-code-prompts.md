# 상식 퀴즈 게임 — 클로드 코드 3단계 프롬프트

PRD v1.0(`quiz-game-prd.md`) 기준. 각 단계 시작 시 **PRD 파일을 프로젝트에 넣거나 첨부**하고, 아래 프롬프트를 붙여넣는다.

| 단계 | 목표 | 끝났을 때 되는 것 |
| --- | --- | --- |
| 1 | 기반 + 퀴즈 코어 | 카테고리를 골라 문제를 끝까지 풀 수 있음 |
| 2 | 결과 + 랭킹 | 완주 → 점수 확인 → 기록 저장 → 랭킹 조회 |
| 3 | 문제 은행 + 마무리 | 40문제 완비, 모바일 대응, 배포 가능 |

---

## 0. 공통 지침

각 단계 프롬프트 앞에 붙이거나, `CLAUDE.md`로 저장해 두면 매번 붙일 필요가 없다.

```
프로젝트 루트의 quiz-game-prd.md를 기준으로 작업해줘.
PRD와 내 지시가 충돌하면 임의로 판단하지 말고 먼저 물어봐.

기술 제약:
- 빌드 도구 없음. 번들러, 트랜스파일러, npm 의존성 모두 사용하지 않는다
- 프레임워크·외부 라이브러리 없이 순수 HTML/CSS/JS
- ES 모듈(<script type="module">)과 fetch를 사용한다
- 개발 중 확인은 `python3 -m http.server`로 한다.
  file:// 로 직접 열면 CORS 때문에 ES 모듈과 fetch가 막히므로,
  파일을 직접 여는 것을 전제로 설계하지 말 것
- localStorage 외의 브라우저 저장소는 사용하지 않는다

코드 구조:
- 게임 로직(출제·채점·타이머 계산)과 DOM 렌더링을 분리한다
- 로직 함수는 DOM을 직접 건드리지 않고, 입력을 받아 값을 반환한다
- 상수(문항당 제한 시간, 출제 문항 수, 문항당 배점)는 한 파일에 모은다

작업 방식:
- 코드를 쓰기 전에 파일 구조와 접근 방식을 먼저 요약해서 보여주고 확인받는다
- 한 번에 전부 만들지 말고 기능 단위로 나눠 진행한다
- 이번 단계 범위 밖의 기능은 미리 만들지 않는다
- UI 문구와 주석은 한국어로 작성한다
```

## 1단계 — 기반 + 퀴즈 코어

```
1단계를 시작하자. 목표는 "카테고리를 하나 골라 문제를 끝까지 풀 수 있는 상태"다.

## 이번 단계 범위

1. 프로젝트 구조 잡기
   - index.html, css/, js/, data/ 구성
   - 화면 전환 방식을 먼저 정하고 설명해줘 (단일 HTML + 화면 토글 권장)

2. 문제 데이터
   - PRD 6.1 스키마대로 카테고리별 JSON 파일 생성 (data/history.json 등)
   - 이번 단계는 동작 확인용 시드 데이터만: 카테고리당 3문제
   - 나머지 문제는 3단계에서 채우므로 지금 40개를 만들지 말 것

3. 데이터 검증 (FR-1.9)
   - 앱 시작 시 보기 개수, 정답 인덱스 범위, 필수 필드를 검사
   - 불량 문제는 출제에서 제외하고 콘솔에 경고

4. 출제 로직 (FR-1.2 ~ FR-1.8)
   - 출제 문항 수는 은행 크기와 분리된 상수로 관리
   - 은행이 출제 수보다 많으면 무작위 표본 추출
   - 직전 판 출제 문제는 후순위 (quiz.recentQuestionIds)
   - 문제 순서와 보기 순서를 매 판 셔플

5. 홈 화면
   - 카테고리 카드 4개. 이번 단계에서는 최고 점수 표시 제외
   - "전체 도전" 버튼은 2단계에서 붙이므로 지금은 만들지 않음

6. 퀴즈 화면
   - 진행률 표시(3/10)와 진행 바
   - 문제 1개 + 보기 4개
   - 키보드 1~4로 선택 (FR-3.5)
   - 나가기 → 확인 후 홈 (FR-3.6)

7. 타이머 (FR-3.7 ~ FR-3.12)
   - 문항당 20초, 남은 시간 시각화
   - 문제 표시 시점 시작, 보기 선택 시 정지, 해설 중에는 정지
   - 남은 5초부터 경고. 색상 외에 숫자나 아이콘도 함께 변화
   - setInterval 카운트다운이 아니라 시작 시각 기준 경과 시간 계산으로 구현
   - 일시정지 없음

8. 즉시 피드백 (FR-4.1 ~ FR-4.4)
   - 정답 초록, 선택한 오답 빨강, 정답 위치 강조
   - 해설 노출
   - "다음 문제" 버튼을 눌러야 진행. 자동 전환 없음
   - 시간 초과도 오답과 동일하게 정답과 해설을 보여줌

## 이번 단계에서 만들지 않을 것
결과 화면, 점수 계산, 랭킹, localStorage 저장, 전체 모드(40문제), 효과음

## 완료 확인 기준
아래를 직접 확인하고 결과를 알려줘.
- [ ] 카테고리를 고르면 시드 3문제를 끝까지 풀 수 있다
- [ ] 20초가 지나면 자동으로 오답 처리되고 해설이 뜬다
- [ ] 해설을 보는 동안 타이머가 흐르지 않는다
- [ ] 다른 탭에 갔다 돌아와도 남은 시간이 어긋나지 않는다
- [ ] 같은 카테고리를 다시 시작하면 문제와 보기 순서가 달라진다
- [ ] 키보드 1~4로 보기를 선택할 수 있다
- [ ] 새로고침하면 처음부터 시작한다
```

## 2단계 — 결과 + 랭킹

```
2단계를 시작하자. 목표는 "한 판을 완주하고 기록을 남겨 랭킹에서 확인할 수 있는 상태"다.

## 이번 단계 범위

1. 점수와 소요 시간
   - 정답당 10점 고정 (FR-5.1). 속도 보너스나 난이도 배점은 넣지 않는다
   - 소요 시간은 각 문항의 응답 시간 합계. 해설 읽는 시간 제외,
     시간 초과 문항은 20초로 계산 (FR-5.3)

2. 결과 화면 (FR-5.2 ~ FR-5.7)
   - 점수, 정답 개수, 정답률, 소요 시간
   - 해당 모드·카테고리의 기존 최고 점수와 비교 표시 (신기록 여부)
   - 점수 구간별 등급 메시지
   - 틀린 문제 목록을 정답·해설과 함께 다시 보기
   - 전체 모드일 때는 카테고리별 정답 개수 분리 표시

3. 저장소 어댑터 (FR-6.8, FR-6.9) — 이번 단계의 핵심
   - saveRecord / getRankings / getBestScore / clearAll 인터페이스를 먼저 정의
   - 모든 메서드는 Promise를 반환한다 (로컬 구현이 동기여도)
   - localStorage 구현체를 별도 파일로 작성
   - 게임 로직과 화면 코드에서 localStorage를 직접 호출하는 곳이 없어야 한다
   - 나중에 서버 구현체로 갈아끼울 때 호출부가 바뀌지 않는 구조인지 설명해줘

4. 랭킹 (FR-6.1 ~ FR-6.7, FR-6.10 ~ FR-6.12)
   - 결과 화면에서 닉네임(2~10자) 입력 후 등록
   - 모드·카테고리별로 분리 관리, 각 상위 10개
   - 정렬: 점수 내림차순, 동점 시 playedAt 오름차순(먼저 달성한 순)
   - 목록에 소요 시간은 표시하지 않는다
   - 방금 등록한 기록 하이라이트
   - 화면 상단에 "이 브라우저에 저장된 기록"임을 명시
   - 마지막 닉네임 기억해서 기본값으로 채우기
   - 기록이 없으면 빈 상태 안내. 가상 기록은 심지 않는다
   - 전체 초기화 (확인 절차 포함)

5. 전체 모드 (FR-2.2)
   - 홈에 "전체 도전" 추가. 4개 카테고리 문제를 섞어 40문제 연속 진행

6. 저장 데이터 안정성
   - quiz.schemaVersion 키 도입
   - 저장 데이터가 손상됐거나 파싱에 실패하면 앱을 죽이지 말고
     빈 랭킹으로 복구 (PRD 8. 데이터 무결성)

7. 홈 화면 보완
   - 카테고리 카드에 최고 점수 표시 (FR-2.3)

## 완료 확인 기준
- [ ] 완주 → 결과 → 닉네임 등록 → 랭킹 목록에 뜬다
- [ ] 같은 점수 기록을 두 번 만들면 먼저 만든 쪽이 위에 온다
- [ ] 브라우저를 껐다 켜도 기록이 남아 있다
- [ ] 개발자 도구로 localStorage 값을 깨뜨려도 앱이 죽지 않고 빈 랭킹으로 뜬다
- [ ] 퀴즈 진행 중 나가면 그 판은 기록되지 않는다
- [ ] 전체 모드 40문제가 끝까지 진행되고 카테고리별 결과가 나뉘어 보인다
- [ ] 코드 전체에서 localStorage 직접 호출이 어댑터 구현체 파일에만 있다
```

## 3단계 — 문제 은행 + 마무리

문제 작성과 폴리시를 한 세션에서 하면 리뷰가 어려우므로, 아래 프롬프트를 **A와 B로 나눠 실행**하는 것을 권한다.

### 3-A. 문제 은행 완성

```
문제 은행을 채우자. 카테고리별로 10문제씩, 총 40문제가 되도록 시드 데이터를 확장해줘.

카테고리: 한국사, 과학, 지리, 일반상식

작성 기준:
- 논쟁의 여지가 없는 사실만. 해석이 갈리거나 출처마다 다른 내용은 피할 것
- 정답이 명확히 하나여야 한다. "가장 알맞은 것"처럼 판단이 필요한 형태는 피할 것
- 오답 보기 3개도 그럴듯해야 한다. 명백히 말이 안 되는 보기는 넣지 않는다
- 난이도는 성인이 절반 이상 맞힐 수준으로 맞춘다
- 해설은 1~2문장. 정답인 이유를 설명하되 문제 문장을 그대로 반복하지 않는다
- difficulty와 tags 필드도 채운다
- 보기 4개의 길이를 비슷하게 유지한다 (정답만 유독 길면 티가 난다)

주의:
- 연도, 수치, 순위처럼 틀리기 쉬운 항목은 특히 신중하게 작성할 것
- 확신이 서지 않는 문제는 그냥 넣지 말고, 작업이 끝난 뒤
  "검증이 필요한 문제" 목록으로 따로 알려줘
- 기존 시드 문제의 ID는 재사용하지 않는다

작성 후 검증 스크립트나 수동 점검으로 아래를 확인해줘:
- 모든 문제의 answerIndex가 실제 정답 보기를 가리키는지
- ID 중복이 없는지
- 카테고리별로 정확히 10문제인지
```

### 3-B. 반응형 · 접근성 · 배포

```
마무리 작업을 하자. 목표는 공개 배포 가능한 상태다.

1. 반응형 (PRD 8)
   - 모바일 우선. 320px 폭까지 레이아웃이 깨지지 않을 것
   - 보기 버튼은 터치하기 충분한 크기로

2. 접근성
   - 키보드만으로 전체 흐름(홈 → 퀴즈 → 결과 → 랭킹)이 가능할 것
   - 정답/오답을 색상만으로 구분하지 않고 아이콘과 텍스트를 병행
   - 보기 버튼에 포커스 스타일이 보이게
   - 타이머 경고를 색상 변화에만 의존하지 않기
   - 화면 전환 시 스크린리더가 새 내용을 읽도록 처리

3. 예외 처리
   - 문제 데이터 로딩 실패 시 사용자에게 안내 (콘솔 에러만 남기지 말 것)
   - 특정 카테고리 문제가 출제 수보다 적을 때의 동작

4. 마감
   - 정답/오답 애니메이션과 효과음 (음소거 토글, 설정은 localStorage 저장)
   - 첫 화면 로딩 1초 이내 확인

5. 배포
   - README 작성: 게임 소개, 로컬 실행 방법, 문제 추가하는 방법
   - GitHub Pages 배포 설정. 경로 문제가 없도록 상대 경로 사용
   - 문제 추가 시 JSON 파일만 고치면 되도록 구조가 유지되는지 확인

## 완료 확인 기준
- [ ] 320px 폭에서 모든 화면이 깨지지 않는다
- [ ] 마우스 없이 키보드만으로 한 판을 완주하고 기록까지 남길 수 있다
- [ ] 화면을 흑백으로 봐도 정답과 오답이 구분된다
- [ ] data/ 의 JSON에 문제를 하나 추가하면 코드 수정 없이 출제된다
- [ ] GitHub Pages 주소로 접속해 정상 동작한다
```

## 단계 사이에 할 것

- 각 단계 끝에서 **직접 플레이해보기.** 확인 기준 체크리스트는 클로드 코드가 놓친 걸 잡아주지 못한다
- 단계별로 커밋을 나눠두면 되돌리기 쉽다
- 1단계 끝나고 나면 실제 화면을 보게 되므로, 여기서 나온 위화감을 2단계 프롬프트에 반영할 것
- 전체 모드 40문제는 최대 13분 20초가 걸린다. 2단계 후 실제로 완주해보고 길다고 느껴지면 문항 수 조정을 검토
